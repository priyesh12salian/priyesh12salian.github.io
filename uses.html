Uses

The tools I actually work with on NetSuite projects, and what each one is for. Nothing here is sponsored or affiliated.

Updated 23 Nov 2026

SDFNetSuite development

  • SuiteCloud Development Framework (SDF) for every customisation. Scripts, records, fields and workflows live in a project folder and deploy from the command line, so nothing is edited by hand in production.
  • SuiteCloud CLI for Node.js to validate and deploy SDF projects, and to pull objects out of an account I am taking over.
  • VS Code with the SuiteCloud extension. One editor for SuiteScript, SuiteQL, XML object definitions and this site.
  • SuiteScript 2.1 for all new code. Arrow functions, template strings and const make scripts shorter and easier to review.
  • SuiteQL with the Records Catalog open in a second tab, for anything a saved search makes awkward.

APIIntegrations and APIs

  • Postman with a collection per integration. Every RESTlet and REST web services call is saved with example payloads before any code is written on the other side.
  • Token-based authentication and OAuth 2.0 for every connection. No user passwords in integrations, ever.
  • Boomi when the client already runs an iPaaS, for EDI and intercompany flows with mapping and retries handled in the process.
  • SFTP clients and the N/sftp module for bank, payroll and partner file exchange, with a status record per file in NetSuite.
  • Sample cXML and EDI documents kept per project, so a parser can be tested without waiting on the partner.

BIData and reporting

  • Saved searches for operational lists and alerts. Still the fastest thing to build and the easiest for an admin to change.
  • SuiteAnalytics workbooks and datasets for pivots and charts inside NetSuite.
  • Power BI over SuiteAnalytics Connect (ODBC) for finance dashboards that mix NetSuite with other sources.
  • SQL as the common language across all of the above.

AIAI tooling

  • Claude and Claude Code for drafting SuiteScript, reviewing it, and writing the documentation nobody wants to write. Every line still gets read before it is deployed.
  • MCP servers I write myself, with tools that map one to one onto narrow RESTlets. This is how agents reach NetSuite in my projects.
  • OpenAI API and Claude for reading invoices and purchase orders into structured data.
  • React for the review dashboards where people approve what an agent proposed.

GITEveryday

  • Git and GitHub for every SDF project and for this site, which is a GitHub Pages repository.
  • GitHub Discussions power the comments and the Ask me anything board here, via giscus.
  • Lighthouse runs on this site after every change. Scores are in the changelog.
  • Markdown for specs, hand-over notes and SOPs, kept next to the code they describe.

This is a uses page. If you want to know how I would set any of this up for your team, get in touch.
